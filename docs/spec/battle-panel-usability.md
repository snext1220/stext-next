# 戦闘欄の折りたたみ・ダイス操作帯の追従仕様

## 状態

実装済み（2026-11-15）。同日、ユーザー承認後に実装・検証。

## 目的と背景

本文の下にある戦闘欄では、敵が縦に並ぶため、下の敵の操作と上のダイス操作を行き来するためのスクロールが必要になる。現在の撃破チェックは敵を薄く表示するだけで、表示の高さは減らない。

撃破チェックで敵カードを折りたたみ、誤操作から戻せる状態を保ちながら一覧を短くする。あわせて、戦闘欄の範囲内でダイス操作帯を追従させ、まだ敵が多く残っている場合も振り直しや出目の確認をしやすくする。

## 合意済みの方針

- プレイヤーと Playground 試遊の両方を対象にする。
- 撃破済みの折りたたみと、ダイス操作帯の追従を今回の対象に含める。
- 折りたたみ中の未取得戦利品は表示だけ残し、詳細を開いて取得する。

以下の具体的な動作を含め、ユーザー承認済み。

## 対象範囲

- 共通戦闘 UI の敵カード、撃破チェック、詳細の開閉。
- 出目・「ダイスを振る」・ダメージ倍率をまとめた操作帯の追従。
- 上記の操作性、状態保持、キーボード操作、狭い画面での表示。

戦闘状態・計算・保存については、[Playground 試遊の戦闘機能仕様](./playground-battle-preview.md)を維持する。敵のいないシーンの表示条件は、[敵のいないシーンでのダイス表示仕様](./scene-dice-ui.md)を維持する。

## 動作仕様

### 撃破チェックと折りたたみ

- 現在と同様、シーンに複数の敵がいる場合だけ撃破チェックを表示する。折りたたみによって見えている敵の数が減っても、チェック欄を消さない。
- チェックを入れると、その敵を撃破済みとして扱い、カードの詳細を折りたたむ。敵自体を一覧から削除せず、元の順序を保つ。
- 折りたたんだカードには、チェック欄、敵名、「撃破済み」、詳細を開く操作を残す。未取得戦利品がある場合は「未取得の戦利品あり」も表示する。
- 折りたたみ中は、属性、攻撃・判定式、敵の説明、HP、戦闘操作、戦利品の取得ボタンを表示しない。
- チェックを外すと撃破チェックを解除し、必ず詳細を開いて元の表示に戻す。
- チェックを付けたまま「詳細を開く」で詳細を表示できる。表示中は「詳細を閉じる」で再び折りたためる。詳細の開閉では撃破チェックを変えない。
- 未チェックの敵は従来どおり詳細を表示する。今回、未チェックの敵を折りたたむ機能は追加しない。
- HP が 0 以下になっただけでは、チェックを自動で付けず、詳細も自動で折りたたまない。HP による既存の撃破表示・攻撃ボタンの無効化は維持する。
- 初期化時の撃破チェックは未チェック、詳細は表示状態とする。

### 状態と戦利品

- チェックや詳細の開閉によって、敵 HP、選択済みの判定式、戦利品と取得状態、ダイス目、倍率、主人公の状態を変更・再初期化しない。
- チェック解除は撃破の目印の解除であり、敵 HP を回復しない。HP が 0 以下なら、チェック解除後も既存の HP による撃破扱いを維持する。
- 折りたたみ中の未取得表示は取得ボタンではない。詳細を開いて既存の戦利品ボタンから取得する。
- 取得すると「未取得の戦利品あり」を消す。詳細では既存の取得済み表示を維持し、開閉やチェック解除で再取得可能にしない。
- 戦利品がない敵や取得済みの敵には、未取得表示を出さない。
- 詳細表示中の戦闘操作の可否と計算結果は既存仕様に従う。チェック解除や開閉を理由に攻撃・戦利品の条件を緩めない。
- 詳細の開閉状態は一時的な UI 状態とし、セーブデータ、LocalStorage、IndexedDB、シナリオ JSON に追加しない。
- 同じ戦闘 UI の主人公状態更新や振り直しでは開閉状態を保持する。シーン移動、ロード、試遊タブの再表示などで戦闘 UI が初期化されるときは、既存の戦闘状態と一緒に初期化する。

### ダイス操作帯の追従

- 出目、既存の振り直し操作、ダメージ倍率を一つの操作帯にまとめる。新しいダイス操作や独立したダイス状態は作らない。
- 敵がいるシーンで追従を有効にする。敵が一体の場合や全員をチェックした場合も同じ動作とする。
- 操作帯は従来どおり戦闘ルールと敵一覧の間に置く。戦闘欄が画面上部の追従位置に達した後、敵一覧をスクロールしている間、操作帯を画面上部に追従させる。
- 追従範囲は操作帯と敵一覧を含む戦闘欄に限定する。本文を読んでいる間や、戦闘欄を通り過ぎて選択肢を読んでいる間に、画面固定の操作帯を残さない。
- プレイヤーではサイトのヘッダーとセーフエリアの下、Playground では試遊を表示しているスクロール領域の上部に合わせる。既存の追従ヘッダーがある場合はその下に置く。
- Playground の狭い画面ではページ全体をスクロールする既存配置に合わせ、試遊タブの内容だけは内側の不要なスクロール領域を作らず、ページ上部のセーフエリア下に追従させる。他の編集タブのスクロール設定は変更しない。
- ヘッダーの折り返し、画面幅の変更、文字の拡大にも追従位置を合わせる。固定のヘッダー高さだけを前提にして重なりを許容しない。
- 操作帯には背景を付け、下の敵の文字が透けて読みにくくならないようにする。ダイアログなど既存の前面 UI より上には表示しない。
- 狭い画面では操作を折り返し、横スクロールを生じさせない。通常の縦画面では操作帯が画面の大半を占めないようにする。
- 敵がおらず `dice` だけが設定されているシーンは、従来の通常配置を維持し、追従させない。倍率を表示しない点も維持する。

### 操作性とアクセシビリティ

- チェック欄と詳細開閉は別の操作にする。敵名の行全体をクリックしただけで撃破チェックを切り替えない。
- チェック欄と詳細開閉はキーボードで操作できるようにする。詳細開閉には敵を識別できる名前と、開閉状態・対象との対応を付ける。
- 折りたたみ中の詳細内の操作は、Tab 移動や支援技術の操作対象にならないようにする。
- チェック後もチェック欄を残し、キーボードフォーカスを失わない。詳細を閉じる操作後も開閉操作にフォーカスを残す。
- 自動スクロールや敵の並べ替えは行わない。カードの高さが変わる自然なレイアウト変化は許容するが、先頭への強制移動は行わない。
- 既存のテーマ、色、フォーカス表示を使う。撃破や未取得を色の違いだけで伝えない。

## 対象外

- 敵の削除、撃破済み敵の別一覧への移動、一括チェック・一括開閉。
- HP に連動した自動チェック・自動折りたたみ。
- 自動戦闘、攻撃時の自動ダイス振り直し、独自戦闘ルールの自動処理。
- 戦闘途中状態の保存・復元、既存のロード時動作の変更。
- 戦闘欄以外の固定パネルや画面全体のレイアウトの刷新。
- シナリオ本文、敵データ、戦闘計算、スキーマの変更。

## 実装方針と影響

- `packages/ui/src/Battle.tsx`、`BattlePanel.tsx`、共通スタイルを中心に変更し、プレイヤーと試遊の操作を共通化したままにする。
- 追従範囲を作るために戦闘欄のまとまりを設ける。追従位置の調整が必要な場合のみ、各アプリのヘッダー・スクロール構造との接続を変更する。
- 追従位置の共有に既存の仕組みがあれば再利用する。戦闘計算や保存処理は変更しない。
- 実装時に [プレイヤーマニュアル](../manual-player.md)と[Playground マニュアル](../manual-playground.md)の戦闘操作説明を更新する。
- 構成上の決定が追加された場合に限り、[プロジェクトノート](../project-notes.md)と[開発手順](../development.md)を更新する。
- 折りたたみは共通カード内に限定できるが、追従は両画面の異なるスクロール構造とヘッダーの検証が必要になる。単純な CSS の追加だけで完了とは判断しない。大きな画面構造変更が必要と判明した場合は、実装範囲を再相談する。

## 完了条件と確認方法

### コンポーネント・統合テスト

- 三体以上の敵で、一体だけチェックしたときにその敵の詳細だけが隠れ、敵名・チェック・開閉操作が残る。他の敵の状態と順序は変わらない。
- チェック解除で詳細が戻り、HP・式・ダイス・倍率・戦利品取得状態が保持される。
- チェックを維持した詳細の開閉、HP が 0 以下になっても自動折りたたみしない動作を確認する。
- 未取得戦利品の表示、詳細を開いて取得する動作、取得後の表示更新、開閉後も再取得できないことを確認する。
- プレイヤーと試遊の両方で、状態更新による不要な再初期化が起きず、既存の戦闘 UI 初期化時には開閉状態も初期化される。
- キーボードによるチェックと開閉、折りたたみ中の操作の非表示・フォーカス除外を確認する。
- 敵一体、全員チェック、敵なしでダイスあり、敵もダイスもなしの既存条件を確認する。
- 変更対象の既存テスト、lint、型検査を実行し、戦闘計算・通知・保存の既存動作を維持する。

### ブラウザーでの表示・スクロール確認

- プレイヤーと試遊の両方で、三体以上の敵と長い説明を使い、下の敵を操作中に上へスクロールせずダイスを振り直せる。表示された出目・倍率がその敵への操作で使われる。
- 本文、戦闘欄内、戦闘欄の後の選択肢へ順にスクロールし、追従の開始位置と終了位置を確認する。戦闘欄を通り過ぎた後に操作帯が画面に残らない。
- 少なくとも幅 390px と 1280px の縦画面、およびブラウザーの 200% 拡大で確認する。ヘッダーとの重なりやページの不要な横スクロールがない。
- チェック・詳細開閉で先頭への強制スクロールやフォーカス消失がなく、全員を折りたたんでもチェック解除・詳細表示・選択肢操作ができる。
- 明暗両テーマで操作帯と敵カードが読め、既存のダイアログが操作帯より手前に表示される。

DOM テストだけで追従の成立を判断せず、実際のスクロール領域・ヘッダーを持つブラウザー画面で確認して完了とする。

## 検証結果

- 共通戦闘欄・プレイヤー・試遊の関連テスト3ファイル、58件が成功。対象コードの ESLint、型検査、両アプリのビルド、変更ファイルの書式検査も成功。
- ブラウザーで五体の敵を持つ確認用シナリオを使い、幅390px・1280pxで振り直し時のスクロール位置保持、ヘッダーとの非重複、不要な横スクロールがないことを確認。
- 200%相当の表示は、1280×900の画面に対して640×450 CSS px・deviceScaleFactor 2のブラウザーエミュレーションで確認。ブラウザーの標準ズーム操作そのものの検証ではない。
- プレイヤーの追従上端は、1280px幅で約51.8px、390px幅で約90.6pxとなり、それぞれ実際のヘッダー下端と一致。試遊は広い画面で内側のスクロール領域、狭い画面でページ上部に追従。
- 戦闘欄の前後で追従が解除されること、倍率×2で下の敵に2ダメージが反映されること、全員の折りたたみと解除、キーボードでのチェック・詳細開閉、戦利品取得後の表示・取得状態保持を確認。
- 明暗両テーマの操作帯背景と、既存ダイアログが操作帯より前面に表示されることを確認。
