# Playground 試遊の戦闘機能仕様

## 状態

実装済み（2026-11-11）。

## 目的

Playground の試遊で、敵が登場するシーンのダイス・敵 HP・攻撃・戦利品を確認できるようにする。プレイヤーと試遊で戦闘の操作・表示・結果通知を共通化し、片方だけに修正が反映される状態を避ける。

## 現状と方針

現在、Playground の試遊は敵名を表示するだけで、戦闘操作はできない。ダイス、敵カードの UI とダメージ・回避・戦利品の計算はすでに共通部品・`@stext/core` にある。一方、戦闘状態の初期化、操作、結果表示、効果音の選択はプレイヤー画面が個別に組み立てている。

共通の戦闘 hook／コントローラーと表示コンポーネントを `@stext/ui` に設け、プレイヤーと Playground の両方から利用する。共通処理は既存の `@stext/core` の戦闘計算を呼び出し、シーン状態の更新結果と戦闘フィードバックを呼び出し元へ返す。セーブ処理、試遊状態への反映、効果音の再生は各アプリが担う。アプリごとの違いを共通層に持ち込まず、共通 UI と操作の二重実装を防ぐ。

## 対象範囲

- 敵が登場するシーンに、戦闘ルール、ダイス、倍率、敵カードを表示する。
- シーンに設定されたダイスを使い、戦闘開始時に振る。再度振る操作も提供する。
- 各敵のダメージ／回避式、HP、戦利品をプレイヤーと同じ規則で初期化する。
- 倍率を指定し、敵の攻撃、プレイヤー側の攻撃、撃破チェック、戦利品取得を操作できる。
- 被ダメージ・回避・能力値低下・状態異常・敵へのダメージ・戦利品取得の結果を表示する。
- ダイス、攻撃、回避、状態異常、戦利品の効果音を、プレイヤーと同じ種類・タイミングで再生する。Playground では既存の試遊音声設定に従い、登録済み効果音があれば優先する。
- プレイヤーの現在の戦闘操作・表示・効果を維持する。

## 動作仕様

### 戦闘状態の初期化と破棄

- 敵のいるシーンに入ったとき、または戦闘 UI を新たに表示したときに、ダイス、敵ごとの式、敵 HP、戦利品を初期化する。
- 同じシーン内で主人公の状態が変化しても、ダイスや敵 HP などの戦闘状態を再初期化しない。
- 別のシーンへ移動したときは、前のシーンの戦闘状態を破棄して、移動先に敵がいれば新しい戦闘状態を作る。
- Playground の試遊タブを離れて戻った場合、シーンの進行状態は現在の仕様どおり保持するが、ダイス・敵 HP・戦利品取得済み状態などシーン内の戦闘状態は初期化する。再表示時にシーンの効果を再適用しない。
- ただし、敵 HP がパラメーター参照の場合、その HP は試遊のシーン状態に含まれるパラメーター値から再計算する。攻撃で更新されたパラメーターは通常の試遊状態として保持し、戦闘状態の初期化で巻き戻さない。
- 戦闘状態はセーブデータ、IndexedDB、LocalStorage に保存しない。

### 戦闘操作

- 「ダイスを振る」はダイス目だけを更新し、敵の式、HP、取得済み戦利品をリセットしない。
- 「敵の攻撃」は現在のダイス目・倍率で敵の攻撃を解決し、主人公の状態を更新する。
- 「攻撃する」は現在のダイス目・倍率で敵 HP を減らす。パラメーター参照の HP は、既存の `attackEnemy` と同様にシーン状態のパラメーターにも反映する。
- 戦利品は敵ごとに一度だけ取得でき、既存の `applyDrop` と同じ効果を主人公の状態へ反映する。
- 複数の敵がいる場合の撃破チェックは、プレイヤーと同じ表示・操作にする。HP が 0 以下の敵は撃破状態として扱う。

### 状態・保存の分離

- 共通戦闘処理は、入力されたシーン状態から新しい状態を計算して返し、アプリの保存先を直接操作しない。
- プレイヤーは、従来どおり戦闘結果をプレイヤーのセーブデータへ反映する。
- Playground は、戦闘結果を現在の試遊状態だけに反映する。試遊結果でプレイヤーのセーブデータや作品データを書き換えない。
- 試遊の状態変更後も、既存どおり試遊タブ切替後の再表示と［直前のシーンからやり直す］が動作する。

### 結果通知・音声

- 戦闘計算の結果を共通形式のフィードバックとして返し、同じ種類の結果に同じ意味のメッセージと効果音を対応させる。
- プレイヤーは既存のトースト表示、Playground は試遊のログまたは既存の通知領域を使う。表示機構はアプリ固有のものを維持する。
- 効果音の URL 解決・再生はアプリ側が担当する。音声設定がオフの場合は再生しない。自動再生制限などのエラー表示は、各アプリの既存音声処理に従う。
- ダイスの振り演出を含め、共通の戦闘 UI は両画面で同じ見た目・操作結果にする。

## 対象外

- タブ切替、再読み込み、シーン移動をまたいだ戦闘途中状態の復元。
- 試遊結果のプレイヤーセーブまたは作品データへの保存。
- 自動戦闘、敵 AI、戦闘バランスの自動判定。
- シナリオ本文に書かれた独自戦闘ルールの自動実行。
- 戦闘計算規則や旧エンジン互換動作の変更。
- Playground の［戻る］選択肢への対応（別の機能差として扱う）。

## 互換性とエラー時の扱い

- 既存の `@stext/core` 戦闘関数と計算結果を維持する。共通化を理由に戦闘仕様を変更しない。
- `@stext/ui` が現在持つ `@stext/core` 依存を利用し、アプリケーション固有の保存・音声実装を共通 UI に直接依存させない。
- 戦闘操作中の例外を成功扱いにせず、既存のエラー表示・通知経路へ明示的に渡す。
- Play の保存タイミング、ロード時の戦闘状態初期化、戦闘結果通知を維持する。

## 完了条件

- プレイヤーとPlaygroundの両方が共通の戦闘 UI・操作処理を利用している。
- 指定ダイスの表示・振り直し、倍率、敵攻撃、回避・ダメージ、能力値攻撃、状態異常、敵 HP、パラメーター参照 HP、戦利品、複数敵の撃破チェックを確認できる。
- シーン移動時に戦闘状態が初期化され、同一シーン内の主人公状態更新では不要な初期化が起きない。
- Playground の試遊タブを離れて戻ると戦闘だけが初期化され、試遊中のシーン・主人公状態は維持され、シーン効果は再適用されない。
- Playground の戦闘操作がプレイヤーのセーブデータ・作品データに保存されない。
- ダイス・戦闘結果の効果音と演出が両画面で揃い、それぞれの既存音声設定に従う。
- 共通処理の単体テストと、プレイヤー・試遊の統合テストで上記動作を確認する。既存のプレイヤー戦闘テストを維持する。

## 実装規模の目安

既存の戦闘計算と基本 UI を再利用する前提で、全体を **2〜4人日程度**と見積もる。共通 hook／表示とテスト、プレイヤーの接続・回帰確認、Playground の接続・試遊固有テスト、文書更新・全体確認を含む。実装着手後に既存のテストや状態遷移との結び付きが想定より強いと分かった場合は、範囲や見積もりを改めて相談する。

## 変更が想定されるファイル

- `packages/ui/`: 共通戦闘 hook／コントローラー、表示コンポーネント、必要な結果フィードバック型とテスト。
- `apps/player/src/screens/Play.tsx`: 共通戦闘機能への接続、既存セーブ・通知・音声との連携。
- `apps/player/src/screens/Play.test.tsx`: プレイヤーでの戦闘動作・保存互換性の確認。
- `apps/playground/src/TestPlay.tsx`: 共通戦闘機能への接続、試遊状態・ログ・音声との連携。
- `apps/playground/src/TestPlay.test.tsx`: 試遊戦闘、タブ切替後の初期化、非保存の確認。
- 必要に応じて `docs/manual-playground.md`、`docs/manual-player.md`、`docs/spec/migration-gap-analysis.md`。

実装前に既存のテストと型を確認し、責務の切り出し先を調整する。`packages/core` の戦闘計算を重複実装せず、無関係なプレイヤー画面のリファクタリングは行わない。
