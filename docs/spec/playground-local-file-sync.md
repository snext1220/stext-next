# Playground ローカルファイル反映仕様

状態：2026-11-11 承認・実装済み。

追加改定：ファイル読み込み時の自動連携（第9節）も2026-11-11 承認・実装済み。

## 1. 目的・範囲

GitHub Pages の Playground で編集・試遊したシナリオを、管理者が手元に clone したリポジトリへ簡単に反映できるようにする。

File System Access API を使い、利用者が明示的に選択した既存のシナリオJSONだけを書き換える。ローカルサーバー、GitHub認証、アクセストークンは不要とする。

画像・音声の書き戻し、フォルダー単位の同期、新規ファイル作成、Git操作、GitHubへの直接反映、自動同期は対象外。従来のブラウザー内自動保存とJSON・ZIPダウンロードは維持する。

関連：[ローカルリソース管理・ZIP出力仕様](./playground-data-management.md)、[Playgroundマニュアル](../manual-playground.md)。

## 2. 配置と表示

上部ツールバーにボタンを追加せず、［エクスポート…］ダイアログの既存ダウンロード操作の下に、区切りと「ローカルファイル連携」欄を追加する。

未連携時：

- 手元のファイルへ編集結果を反映する機能であることを説明する。
- ［保存先ファイルを選択…］を表示する。

連携時：

- 保存先のファイル名とシナリオIDを表示する。APIから取得できない親フォルダーや絶対パスは表示しない。
- ［ローカルへ反映］［保存先を変更…］［連携を解除］を表示する。
- 最後に反映した日時を、反映成功後に表示する。

API非対応時は対応するChrome／Edgeなどの利用と従来のJSONダウンロードを案内し、利用できない連携操作は表示しない。HTTPSまたはlocalhostなど、APIを利用できる環境でのみ提供する。

## 3. 保存先の選択

1. 利用者のボタン操作からファイル選択画面を開き、既存のJSONファイルを1件選択する。
2. 内容を読み、編集用の検証でstext/2として読み込めることを確認する。旧XML・旧Playground JSON・空ファイルは対象外とする。
3. 編集中のシナリオと保存先の `meta.id` がいずれも空でなく一致することを確認する。不一致・未設定なら連携を拒否して理由を表示する。
4. 内容が異なる場合は「現在の編集内容でこのファイルを置き換える保存先として連携する」旨を確認する。公開版と手元の版の新旧は自動判断できず、手元の変更を消す可能性も明示する。
5. 確認後、ファイルハンドルと読み込んだ内容を連携情報として保持する。選択・連携しただけでは書き込まず、編集中のシナリオも置き換えない。

ファイル選択や確認を取り消した場合は既存の連携を維持する。不正なファイルや読み込み失敗の場合は理由を表示し、既存の連携を変更しない。

## 4. ローカルへの反映

1. ［ローカルへ反映］の操作時点のシナリオを確定し、そのスナップショットを書き込む。未完成な値を含む編集用データも、通常のJSONダウンロードと同様に保存できる。
2. 保存先のIDと編集中のIDの一致を再確認する。編集中にIDを変更した場合は反映を停止し、保存先の選び直しを案内する。
3. 必要な書き込み権限を利用者に要求する。許可されなければ失敗として通知し、成功表示しない。
4. 書き込み直前に保存先を読み直し、連携時または直前の反映成功時の内容と文字列で比較する。外部変更があれば書き込まず、VS Codeなどで内容を確認してから保存先を選び直すよう案内する。強制上書き操作は用意しない。
5. UTF-8のJSON（2スペース字下げ・末尾改行）として書き込み、書き込みストリームの終了成功後にのみ成功を表示し、比較用の内容と反映日時を更新する。

処理中は関連ボタンの多重実行、作品切替・新規読み込みなど反映対象の取り違えにつながる操作を防ぐ。処理中に編集を続けられる場合でも、保存されるのは操作開始時点の内容であることを明示する。

ファイル削除・移動・権限拒否・読み書き失敗は画面に通知する。失敗時に比較用の内容を更新しない。書き込み開始後に失敗した場合は、元ファイルが保全されたと断言せず、内容確認を案内する。

外部変更の検出は書き込み直前の比較によるもので、別アプリとの排他制御ではない。確認直後から書き込み完了までの外部更新を完全には防げないため、反映中は同じファイルを他のアプリで保存しないよう案内する。

## 5. 連携の保持範囲

- 連携情報はシナリオIDではなく、既存のブラウザー内作品IDに紐付ける。同じシナリオIDを持つ別作品へ連携を流用しない。
- 同じタブで作品を切り替えて戻った場合は、その作品の連携を復元する。
- 初期実装はメモリー内のみとし、ページ再読み込み・タブ終了後は保存先を選び直す。ファイルハンドルのIndexedDBへの永続保存は対象外とする。
- 作品削除時に対応する連携情報を破棄する。
- ［連携を解除］は連携情報だけを破棄し、ブラウザー内作品やローカルファイルを削除しない。

## 6. 互換性・運用

既存の保存データ・シナリオ形式・素材参照・公開処理は変更しない。JSONだけを反映するため、新規登録した素材は従来のZIPなどで別途反映する。

反映後はVS Codeのソース管理で差分を確認し、通常どおりコミット・pushする。GitHub Pages上の公開データは、ローカル反映だけでは更新されない。

旧形式から変換したシナリオは、再変換で編集結果を失う可能性がある旨を連携欄とマニュアルで案内する。原本の切り替えや変換器の変更は今回の対象外とする。

## 7. 完了条件・確認方法

- エクスポートダイアログから保存先を選択し、明示的な反映操作でのみJSONを書き換えられる。
- 選択の取消・不正JSON・形式違い・ID不一致・外部変更・権限拒否・読み書き失敗をテストし、意図しない書き込みや成功表示がない。
- 反映成功後の再反映、保存先変更、解除、作品切替・削除、同一IDの別作品、多重操作、非対応環境をテストする。
- 既存のJSON・ZIP出力と自動保存のテストを維持し、関係するテスト・型検査・lintで確認する。
- ブラウザー確認では画面と連携操作を検証する。自動化でOSのファイル選択・実書き込みを扱えない場合はAPIモックによる検証と区別し、Chrome／Edgeでの実操作の未確認点を報告する。
- マニュアル・開発ガイド・決定事項を実装に合わせて更新する。

## 8. 実装と確認結果

- ファイル操作と作品別の連携状態は `apps/playground/src/localFileSync.ts`、表示は `WorkspaceMenus.tsx`、編集・作品削除との接続は `App.tsx` に実装した。連携処理中は編集も一時停止する。
- ファイル操作・ダイアログ・アプリ統合・既存ZIP出力・既存保存の関連テスト49件、リポジトリの型検査、変更したTypeScriptのlint、変更したコードの整形確認、Playgroundのビルドを確認した。
- Chromiumの実画面で表示、狭い画面での収まり、再読み込み後の連携解除を確認した。ファイル選択APIだけを差し替えて、ブラウザーの実際のファイルハンドルと書き込みストリームを使い、オリジン専用ファイルシステム（OPFS）上で反映・外部変更時の停止も確認した。
- OSのファイル選択ダイアログでリポジトリのファイルを指定する操作と、実際の権限許可ダイアログは未確認。自動テストのAPIモックおよびOPFSでの検証とは区別する。

## 9. 追加改定：ファイル読み込み時の自動連携

### 目的・操作

ローカルファイルから編集を始める場合に、同じファイルを保存先として選び直す手間をなくす。第3節の手動連携は、公開シナリオから編集を始める場合などのために残す。

- 対応環境では［作品…］の既存の［ファイルを選択…］でFile System Access APIのファイル選択を使う。JSONとXMLの両方を選択でき、新しいボタンは増やさない。
- この欄に「stext/2 JSONは読み込み後に保存先としても連携する。書き込みは［ローカルへ反映］で行う」旨を表示する。
- 有効なシナリオIDを持つstext/2 JSONを読み込んだ場合、作成に成功した新しいブラウザー内作品に、そのファイルを自動で連携する。既存作品の連携は移し替えない。
- 外部変更の比較基準には、実際に読み込んだ元ファイルの内容をそのまま保持する。読み込み後の自動レイアウト・スキーマによる補完後のJSONを基準にはしない。
- 読み込むファイルそのものを保存先にするため、内容差分による連携確認は行わない。読み込み完了の案内で、保存先にも連携したことと、まだ書き込んでいないことを伝える。
- 読み込み時には書き込み権限を要求せず、書き込みストリームも作成しない。編集後は［エクスポート…］→［ローカルへ反映］で、従来どおり権限確認・ID確認・外部変更検出を行う。

### 例外・互換性

- IDが未設定または空白のstext/2 JSONは、従来どおり読み込めるが自動連携しない。その理由と、IDを設定後に［保存先ファイルを選択…］で連携する必要があることを案内する。反映には保存先側にも同じIDが必要である旨も伝える。
- 旧XML・旧Playground JSONは従来どおり変換して読み込むだけとし、元ファイルへは連携・書き戻ししない。
- 非対応環境・安全でない接続環境では既存のファイル入力を維持し、自動連携しない。書き出しにはJSON・ZIPダウンロードを使える。
- 選択の取消は何も変更しない。選択・読み込み・変換・作品作成に失敗した場合はエラーを通知し、誤った作品への連携を残さない。対応環境でAPIが失敗した場合に、黙って別のファイル選択へ切り替えない。
- 読み込み処理中は多重実行・作品切替・他の読み込みなどを防ぎ、読み込み対象と作成先作品の対応を確実にする。
- 自動連携も第5節と同じ保持範囲とする。ページ再読み込み後はファイルを読み直すか、既存のブラウザー内作品に対して保存先を選び直す。

### 完了条件

- 1回のファイル選択でstext/2 JSONを読み込み、編集・反映まで進める。選択・読み込み時に書き込みが発生しないことを確認する。
- 元の文字列を基準とした外部変更検出、読み込み後のID変更、同一IDの別作品への分離をテストする。
- ID未設定、旧XML、旧Playground JSON、非対応環境、選択取消、読み込み失敗、作品作成失敗、多重操作をテストする。
- 手動連携と既存の読み込み・JSON／ZIP出力・自動保存を維持し、関係するテスト・型検査・lint・ビルドを確認する。
- マニュアル・開発ガイド・決定事項を改定内容に合わせて更新する。

### 改定後の確認結果

- 関連テスト59件で、1回の選択からの反映、読み込み時の書き込み・権限要求の不実施、元の文字列による外部変更検出、旧形式・ID未設定・失敗時・非対応環境・多重操作を確認した。型検査、関係するコードのlint・整形確認、Playgroundビルドも通過した。
- Chromiumの実画面でも、ファイル選択APIだけを差し替え、OPFS上の実ファイルハンドルで「ファイルを選択→読み込みと自動連携→本文編集→反映」を確認した。ファイル選択回数は1回、読み込み直後のファイル内容は変更なし、反映後は編集内容に更新された。
- OSのファイル選択・権限許可ダイアログの実操作は引き続き未確認。
