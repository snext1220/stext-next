# 「トラベラーズ☆イン」v2移行仕様

## 目的と範囲

旧シナリオ「トラベラーズ☆イン」（`inn`）を、物語やゲームのルールを尊重したまま、現在のプレイヤー操作と自動処理に合わせる。移行に関係しない文章の校正・改稿、難易度調整、新しい結末や実績の追加は行わない。

旧XML `../stext/stext/inn/scenario.xml` は参照用であり、[`scenarios/inn/scenario.json`](../../scenarios/inn/scenario.json) を原本として直接編集する。旧リポジトリには変更を加えない。

この作品は「30シーン限定シナリオ」だが、自動化に必要な最小限のシーン追加は許容する。追加数と理由を報告し、一覧の実シーン数を更新する。作品紹介の祭り名や、原作が30シーン限定であったことは事実として残す。

## シナリオ原本の管理

- `inn` を含む `scenarios/` の既存シナリオは、v1由来のものも変換済み v2 JSON を原本として管理する。既存作品の更新のために旧XMLから再変換しない。
- 今回、変換CLIの再変換保護機能や原本の識別ファイルは追加しない。旧データの新規取り込みに用いる変換機能自体の削除は対象外とする。
- 再変換を前提にしたリポジトリ指示、移行スキル、開発手順を新方針に合わせて見直し、過去の変換レポートが現行作品の状態を示すと誤解されないようにする。既存の作品一覧・素材・他作品は意図せず変更しない。
- 大きなシーン変更が必要な操作は、自動化に固執せず手動更新も検討する。手動更新を維持する場合は、ユーザーに確認してから決定する。この方針を移行スキルにも反映する。

## 表示と自動処理

- `FREE1` は財布として使われており、表示名を「所持金」とする。本文でも表示名を使い、内部の `free1`、既存セーブの値、敵の計算式などは維持する。未使用の `FREE2`、`FREE3` は新しい用途や表示名を作らない。
- 入場時に無条件で発生する固定の効果は、現行エンジンで再現できるものを `effects` に移し、文章は自動で変化した結果として最小限修正する。少なくとも客室への侵入（シーン1000）のKRM減少、聖水を飲む場面（3250）のMP減少を対象とする。既存の効果を重複させず、再訪・戻る時も旧来の適用回数と矛盾しないことを確かめる。
- 宿泊（6000）は、所持金・支払い・不足時の換金所への移動を判定したうえで、実際に宿泊する場合だけ20 Goldの支払い、HP・MP各15回復、状態異常の解除を反映する。必要な分岐シーンを追加してよい。支払えない場合に無料で回復できず、換金後に二重徴収や二重回復が生じないようにする。元の「1年間過ごす」無料の扱いは変更しない。
- ジャグリング（4200）とモンスター退治（4300）の参加料は、参加時に50 Goldを反映する。料理の注文は正解・不正解それぞれの移動先（2200・2300）で50 Goldを反映し、任意のヒント代は手動のままにする。換金所（7000）は、ユーザーの指定により換金を手動のままとし、換金用のシーンは追加しない。勝敗やプレイヤーの操作が必要な報酬は、参加しただけで勝利扱いにせず、実際の戦闘操作や勝利条件と整合させる。モンスター退治の賞金は、ユーザーの指定により既存の戦利品設定に合わせて70 Goldとし、本文の100 Goldを修正する。
- 謎解きの失敗（2300）の「同じ日に2回以上」の罰や、賭博・盗み・ジャグリングなどの可変額は、元の条件・タイミングを再現できるものだけ自動化する。日にちや任意入力を正確に判定できない場合は手動操作を残し、現在の画面名で明確に案内する。換金はユーザーの指定により元の文章をほぼ維持する。現行プレイヤーでは売却したアイテムを手動で削除できない制約がある。推測によって罰や報酬を変更しない。
- `Battle Sheet` など旧画面の名前を現行UIに合わせる。戦闘欄の「ダイスを振る」「敵の攻撃」、戦利品の取得など、プレイヤーが実際に行う操作や回数・順序は残す。敵の攻撃を受ける場面と単なるダイス判定を区別する。

## サマリとグループの追加

作品の内容を分析し、全31シーンにそれぞれ短い `summary` を付ける。場面の内容を識別しやすくしつつ、エンディングや謎の答えを必要以上に明かさない。既存の `meta.showSummary` は変更せず、プレイヤーの見出しはこれまでどおりシーン番号とする。

シーン番号の範囲に応じて、次のグループを追加する。範囲は両端を含み、互いに重ならない。

| 範囲 | グループ名 | 内容 |
| --- | --- | --- |
| 0〜999 | はじまり | 宿屋の紹介と行動選択 |
| 1000〜1999 | 客室 | 客室への侵入と遭遇 |
| 2000〜2999 | 羊皮紙と食事 | 依頼、謎解き、食事の調達 |
| 3000〜3999 | アイテムの陳列棚 | 陳列された品とその顛末 |
| 4000〜4999 | 賭博場 | ダイス賭博、ジャグリング、腕試し |
| 5000〜5999 | 王女さまとジョセフィーヌ | 王女さまの依頼と散歩 |
| 6000〜6999 | 宿泊と翌朝 | 自室での宿泊と翌日の行動 |
| 7000〜7999 | 換金と旅立ち | 換金と結末 |

- グループにはタイトルと範囲だけを設定し、`bgm`・`rule`・`text` は追加しない。これによりBGMは従来モードを維持し、既存の曲の継続や戦闘ルールを変更しない。
- 本文、選択肢、遷移、効果、既存ID、シーン数やセーブデータの形式は変更しない。
- 移行スキルにも、物語を分析して各シーンのサマリと適切なグループを追加・確認する手順を記載する。既存の設定やBGM・戦闘ルールへの影響を確認し、利用者の指定や作品の事情があれば優先する。
- `validateScenario`・`checkScenario` で範囲と参照を検査し、全シーンにサマリと重複しないグループがあること、従来BGMモードとシナリオ本文・選択肢・効果が変わらないことをテストする。Playground のフローで表示を確認し、未実施なら報告する。

## 互換性と検証

- 既存のシーンID・アイテム・フラグ・実績IDを維持し、保存済みデータの読み込みを妨げない。旧セーブの手動操作と新しい自動効果の二重計算は対応対象外とする。旧セーブ専用のシナリオ本文・選択肢は設けず、それらを制御する専用フラグも使わない。
- スキーマ検証と `checkScenario` に加え、実際のエンジンでKRM・MP減少、参加料、宿泊費と回復、残金不足、換金後の再訪、戻る、主要な既存ルートと実績を確認する。所持金の境界値、状態異常、HP・MPの上限もテストする。
- 料理の購入、換金の手動操作、および既存セーブの読み込みを確認する。旧セーブでの二重計算は検証の対象外とする。原文との差分を確認し、移行に不要な変更を含めない。
- 現行プレイヤーで手動ダイス、敵の攻撃、戦利品、所持金の編集、宿泊と換金を確認する。ブラウザー確認や特定のルートを実施できない場合は未実施と報告する。
