# Playground ローカルリソース管理・ZIP出力機能 仕様書

## 1. 目的

Playgroundに、シナリオJSONおよび画像・音声素材をブラウザー内で一元管理する機能を追加する。

ユーザーは、シナリオJSONを編集しながら、画像・音声素材を個別に読み込み、差し替え、試遊に反映できるものとする。編集・登録したリソースはブラウザー内に保存し、最終的にシナリオJSONと画像・音声素材をまとめたZIPファイルとしてダウンロードできるようにする。

今回の機能追加に伴い、現在の読み込み・保存機能も整理し、各機能の役割と操作方法を明確にする。

投稿との連携は、[作品提出方法の変更計画](./playground-submission-plan.md)に従う。共通素材の除外、ZIP生成時のデータ確定、素材不足の通知、提出前のシナリオIDの確認は、両文書で共通の方針とする。

## 2. 基本方針

### 2.1 保存先

データの種類ごとに保存先を分ける。

| データ | 保存先 | 用途 |
|---|---|---|
| シナリオJSON | IndexedDB | シナリオの編集内容・保存 |
| 画像・音声ファイル | IndexedDB | 素材の実体を保存 |
| 設定・UI状態 | LocalStorage | 選択中のローカル作品の識別情報、表示設定など |

画像・音声などのバイナリデータはLocalStorageに保存しない。容量制限やBase64変換による容量増加を避けるため、Blob形式などでIndexedDBに保存する。

シナリオJSONの編集内容もIndexedDBを基本の保存先とする。LocalStorageは小規模な設定情報に限定する。

### 2.2 ローカル素材の扱い

画像・音声は、ユーザーが個別にローカルファイルを指定できるようにする。

指定されたファイルは、その時点でIndexedDBに実体を保存する。元のローカルファイルへのパスや、一時的なオブジェクトURLだけに依存してはならない。

これにより、元ファイルが移動・削除されても、Playground内に保存された素材を継続して利用できるようにする。

### 2.3 ZIP出力

シナリオJSONと登録済みの画像・音声素材をZIPファイルとしてダウンロードできるようにする。

ZIPには、JSONから参照されている素材だけでなく、ユーザーが指定・登録した素材をすべて収録する。JSONから参照されていない素材も除外しない。

ただし、共通素材は収録せず、既存の参照を維持する。収録する登録素材は、出力対象のシナリオに属する固有素材とする。

## 3. リソース管理機能

### 3.1 シナリオJSON

以下の機能を提供する。

- JSONファイルの読み込み
- JSONの編集
- 編集内容のIndexedDBへの保存
- 保存済みJSONの再読み込み
- JSONファイル単体でのダウンロード
- ZIP出力への収録

編集内容は適切なタイミングでIndexedDBに自動保存する。編集操作のたびに無制限に保存処理を実行するのではなく、一定時間の入力停止後などにまとめて保存する方式を検討する。

保存処理が失敗した場合は、ユーザーにエラーを通知する。保存完了前に「保存済み」と表示してはならない。

編集中の未完成な値は自動保存・復元・JSON読み込み・ZIP退避を妨げない。読み込みには編集に必要な構造・型を確認する検証を使い、正式な形式や整合性の問題は［検査］で表示して修正できるようにする。試遊には正式な形式の検証を残す。構造を読み込めない作品があっても作品一覧全体を止めず、その作品にエラーを表示して元の保存データと素材を残す。

### 3.2 画像・音声素材

画像・音声ファイルを個別に指定・登録できるようにする。

提供する操作は次のとおり。

- 素材の新規登録
- 登録済み素材の差し替え（上書き）
- 素材の削除
- 登録済み素材の確認
- ZIP出力対象の確認

素材の登録時には、シナリオ内で参照される相対パスを基準に管理する。

例えば、シナリオが `capture/scene01.png` を参照している場合、その参照先に対応するローカル画像を指定できる。差し替え時には、同じ参照パスに対応する素材を上書きする。

元の素材ファイルを直接変更するのではなく、IndexedDB内に保存した素材を置き換える。

### 3.3 素材の管理単位

素材はシナリオ単位で管理する。

シナリオIDの扱いは投稿計画を優先する。IDが未設定・不正でもローカル編集と素材登録は可能とし、ZIP作成前にシナリオ本体のIDの修正を促す。修正が完了するまではZIPを生成しない。ZIPのルートフォルダー名とファイル名には、確定したシナリオIDを使う。

ローカルの作品識別は公開用のシナリオIDだけに依存させない。IDの設定・変更で登録素材との対応が失われず、同じIDを持つ別作品の素材が混ざらないようにする。

初期実装では、作品ごとにブラウザー内でUUIDを発行し、公開用のシナリオIDとは別に保存する。新規作成、テンプレート・公開シナリオ・ファイルからの読み込みは、それぞれ独立した作品として登録する。同じシナリオIDのJSONを読み込んでも既存作品を上書きしない。既存の自動保存データは初回に作品として移行する。旧マイストレージ機能は廃止し、名前付き保存を新しい作品一覧へ統合する移行処理も設けない。

素材は IndexedDB の別ストアに保存し、作品UUIDと正規化した相対パスの組を一意キーとする。登録可能な相対パスは `capture/`、`bgm/`、`bgm/se/`、`chara/` 以下とし、画像は PNG・JPEG・GIF・WebP、音声は MP3・OGG・WAV・M4A・AAC、1ファイル50MB以下に制限する。パスの形式と拡張子・MIMEタイプを検査し、不正なパスや拡張子とファイル種別が一致しない素材は登録しない。参照を自動抽出できる画像・BGM・効果音は素材パネルに表示する。未参照素材は登録先の種類（`capture/`、`bgm/`、`bgm/se/`、`chara/`）を選んで登録し、ファイル名はアップロード元の名前を使う。種類に応じてファイル選択の拡張子を絞り、登録時にも形式を検証する。登録済みの同一パスを差し替える際は確認する。

素材の管理情報には、少なくとも次の項目を含める。

- ローカルの作品識別情報（シナリオと素材の対応付けに使用）
- シナリオID（未設定を許容し、ZIP作成前に確定する）
- 素材の相対パス
- ファイル名
- MIMEタイプ
- ファイル実体（Blob）
- 登録日時
- 更新日時

同じシナリオ内で相対パスが重複する場合は同一素材として扱い、上書き確認を行う。

画像・音声の登録時には、可能な範囲でファイル形式やサイズを検証する。不正なパスや許可されていない形式のファイルは登録しない。

## 4. 試遊機能との連携

試遊時には、IndexedDBに登録されているローカル素材を優先して使用する。ローカル素材が登録されていない場合は、従来の素材参照方法を利用する。

これにより、従来の試遊機能との互換性を維持する。

- 画像は、ローカル素材を指定した時点で試遊画面に反映する。
- 音声は、ローカル素材を指定した後に試聴できるようにする。
- 実際のシナリオ試遊時にも、指定した音声を使用する。
- ローカル素材の登録・差し替えによって、シナリオJSON内の素材参照パスを不用意に変更しない。

試遊で表示・再生できることと、提出ZIPに素材がそろっていることは区別する。ZIP作成・提出前の検査では、シナリオが参照する固有素材が未登録なら、従来の外部配信先で表示・再生できても不足として対象パスを通知する。外部配信先から自動取得して不足を隠さない。共通素材は未登録・未収録でも不足扱いにしない。

## 5. ZIP出力機能

### 5.1 基本仕様

IndexedDBに保存されているシナリオJSONと画像・音声素材をまとめてZIPファイルとして出力する。

ZIPファイルはブラウザー内で生成し、サーバーを経由せずにダウンロードできるようにする。

生成前に、シナリオIDを確認し、保留中のシナリオ編集と素材の登録・差し替え・削除の保存を完了させる。保存に失敗した場合はエラーを通知して生成を中止し、古い保存内容で代替しない。

保存完了後、対象作品のシナリオJSONと登録素材について、同一時点のスナップショットをIndexedDBの単一読み取りトランザクションで取得してZIPを生成する。スナップショットの取得中は作品の編集・切り替え操作を無効化し、取得後の編集は生成中のZIPに反映しない。投稿フォームを開くときも同じ保存・スナップショット取得を行い、フォームの初期値と添付シナリオにそのスナップショットを使う。

### 5.2 ZIPのフォルダー構成

現在のシナリオのディレクトリー構成を基本的に維持する。

例：

```text
my-scenario/
  scenario.json
  capture/
    scene01.png
    scene02.png
  bgm/
    main.mp3
    se/
      door.mp3
      attack.mp3
  chara/
    hero.png
    villain.png
```

実際のフォルダー名やJSONのファイル名は、現在のPlaygroundおよびシナリオ形式に合わせること。

共通素材はZIPに収録せず、既存の参照ルールを維持する。シナリオ固有素材は対象シナリオのフォルダー内に収録し、共通素材のコピーや参照先の書き換えは行わない。プレイヤー本体も収録しないため、ZIP単体で動くアプリではない。

### 5.3 収録対象

出力対象のシナリオについて、生成前に確定したスナップショットから、次のすべてを収録する。

1. 最新のシナリオJSON
2. IndexedDBに登録されているシナリオ固有の画像素材
3. IndexedDBに登録されているシナリオ固有の音声素材
4. JSONから参照されていない登録済みのシナリオ固有素材

JSONから参照されていないことを理由に登録済みの固有素材を除外してはならない。共通素材、別作品の素材、投稿用の連絡先・ダウンロードURL・ダウンロードキーは収録しない。

### 5.4 ZIP生成時の注意事項

- シナリオ固有素材は、JSONの参照ルールに対応するZIP内のパスに配置する。共通素材の参照は、ZIP内に実体がなくても維持する。
- 素材のフォルダー階層を維持する。
- 同一パスへの重複登録を防止する。
- ZIP内でファイル名やパスが衝突する場合は、ユーザーに通知するか、安全な方法で解決する。
- ZIP生成中は処理状況を表示する。
- 生成に失敗した場合は、原因をユーザーに通知する。
- スナップショット取得後のZIP生成処理自体は、IndexedDB内のデータを削除・変更しない。生成前の保留中データの保存とは区別する。

ZIP生成には、ブラウザー上で利用できるZIPライブラリを使用してよい。既存の依存ライブラリがあれば、まずその利用可能性を確認する。

Playgroundでは `fflate` のストリーミング ZIP API を使い、画像・音声は再圧縮せずに収録する。入力データを順に読み込んでZIPを組み立て、処理したデータ量を進捗として表示する。

## 6. 読み込み・保存機能の整理

「ブラウザー内に保存すること」と「ファイルとして取り出すこと」を別の操作として示す。IndexedDBへの自動保存を通常の保存方法とし、手動の「保存」ボタンは設けない。保存状況は画面上に表示し、利用者がブラウザー内に保存された状態と分かるようにする。

| 操作 | 役割 |
|---|---|
| 自動保存 | 編集中のシナリオと素材をIndexedDBに保存する。保存中・保存済み・保存失敗を表示する |
| JSON読み込み | ローカルファイルからシナリオJSONを読み込み、新しい作品または選択した作品として開く |
| JSONエクスポート | シナリオJSON単体をローカルファイルとしてダウンロードする |
| ZIPエクスポート | シナリオJSONと登録済みのシナリオ固有素材をまとめてダウンロードする |

エクスポートはファイルをローカルPCへ取り出す操作であり、IndexedDBへの保存とは区別する。ZIPとJSONは「保存」ではなく「エクスポート」または「ダウンロード」と表記する。

作品の新規作成・テンプレートや公開シナリオからの作成・ファイルからの読み込み・保存済み作品の切り替え・削除など、作品全体を出し入れ・管理する操作は「作品」メニューにまとめる。保存はIndexedDBへの自動保存と作品一覧に一本化し、旧マイストレージの名前付き保存機能は設けない。

## 7. UIの整理

作品全体の出し入れ・管理と、開いている作品の編集を別の場所にまとめる。

### 7.1 上部メニュー

- **作品**：新規作成、テンプレートから作成、公開シナリオから作成、JSON・旧XMLの読み込み、保存済み作品一覧と切り替え・削除、作品の複製など。
- **エクスポート**：作品一式（ZIP）とシナリオのみ（JSON）のダウンロード。ZIPを主要項目として扱い、JSONは補助的な選択肢にする。ZIP機能が未実装の間は、使用できる項目だけを表示する。
- **提出…**：ZIPの作成、ギガファイル便へのアップロード、オレンジフォームへの投稿情報送信を案内する独立した操作。別タブで確認・最終送信する。ZIP出力処理はエクスポートと共通化し、提出専用の別形式は作らない。ZIP本体はオレンジフォームへ送信しない。

メニューは一段のサブメニューまたは一覧画面とし、作品名や保存日時の一覧を狭いドロップダウンに詰め込まない。メニューを開く操作はクリック・タップとし、外側クリックやEscで閉じられるようにする。キーボード操作と小さい画面にも対応する。

保存済み作品を削除する場合は、作品とその作品に属する登録素材を同時に削除することを確認する。編集中の作品を削除した場合は、自動保存による復活を防ぎ、空の新しい作品へ切り替える。

### 7.2 編集パネル

素材は上部メニューではなく、既存の編集タブと同列の「素材」パネルに追加する。タブは「シーン」「定義」「素材」「検査」「試遊」を基本とし、シーン本文など作品内容の編集をパネルに集める。

素材パネルにはシナリオ内の参照パスごとに、次の情報・操作をまとめる。

- 画像、BGM、効果音など種類別の登録済み素材一覧。
- 素材のプレビュー、相対パス、登録状態、元ファイル名。
- 新規指定、差し替え、個別の登録解除・削除。
- JSONから参照されていない登録素材も含む、ZIP出力対象の確認。
- 保存状態と、登録素材の容量・エラー。

UI上では「元のローカルファイルを上書きする」のではなく、「Playground内に登録したコピーを差し替える」ことを明示する。登録した素材はこのブラウザーに保存され、試遊とZIP出力に使われる。登録だけでサーバーへアップロード・公開されることはない。

登録済み素材を解除・削除すると、その素材はZIPに含まれなくなる。試遊では従来の素材参照先に素材があればそちらを使う。削除前に対象を示し、「すべて解除」は初期版では設けない。後から追加する場合は、全登録素材が削除されることを確認する操作を必須にする。

試遊とZIPの内容が同じとは限らないことも表示する。シナリオ固有素材は、外部配信先で表示・再生できてもIndexedDBに未登録なら「ZIPに未収録」と不足を通知する。共通素材はZIPに含めないため、不足扱いにしない。

### 7.3 保存・エクスポート状態

- IndexedDBへの自動保存状態（保存中・保存済み・保存失敗）。「保存済み」は書き込みの完了後だけ表示する。
- 保存失敗時のエラーと再試行手段。
- ZIP生成中の進行状況と失敗時の原因・対象ファイル。
- 未登録のシナリオ固有素材など、ZIPに不足するものの警告。
- 「このブラウザーに保存済み」と「ファイルにエクスポート済み」を混同させない表示。

UIは既存のPlaygroundのデザインに合わせ、作品操作・編集・エクスポートの違いを分かりやすく示す。ボタンやメニューの名称は、実装時に既存の画面幅・アクセシビリティを確認して調整する。

## 8. データの整合性・エラー処理

次の点に注意して実装する。

- IndexedDBへの保存が完了する前に保存済みと表示しない。
- ブラウザーの保存容量不足を検知し、不要な素材の削除などの対処をユーザーに案内する。
- IndexedDBのデータが消去された場合に備え、ZIP出力などによる外部バックアップを可能にする。
- 素材の登録・差し替え・削除が途中で失敗しても、既存データを不整合な状態にしない。
- ZIP生成時に素材の読み込みに失敗した場合は、対象ファイルを明示する。
- ファイルパスの正規化を行い、ZIP内に不正なパス（パストラバーサルなど）が作られないようにする。
- ブラウザーを閉じたり再読み込みしたりしても、IndexedDBに正常保存されたデータは復元できるようにする。

## 9. 実装・確認の進め方

実装前に、現在のPlaygroundのソースコードを確認すること。

特に次の点を調査する。

1. 現在のJSON読み込み・保存処理
2. 現在の試遊機能における画像・音声の読み込み方法
3. シナリオJSON内の素材参照パスの形式
4. 画像・音声のディレクトリー構成
5. 共通素材の管理方法
6. 既存の依存ライブラリ

既存の機能やデータ形式を不用意に変更しないこと。特に、現在の試遊機能を維持したまま、段階的に変更する。

実装後は、少なくとも次のテストを行う。

- JSONを読み込み、編集後にブラウザーを再読み込みしても編集内容が残ること。
- 画像を個別に指定し、試遊に反映されること。
- 音声を個別に指定し、試遊に反映されること。
- 指定した素材を差し替えられること。
- 指定した素材を削除すると、元の素材に戻ること（元の素材が利用可能な場合）。
- 元のローカルファイルを移動・削除しても、IndexedDBに保存された素材が利用できること。
- JSONから参照されていない素材もZIPに収録されること。
- 共通素材・別作品の素材・投稿用の連絡先やキーがZIPに収録されず、共通素材の参照が維持されること。
- 編集直後のZIPにも最新の内容が入り、保存失敗時は古い内容でZIPを生成しないこと。
- ZIP生成中の編集・素材変更がスナップショットに混ざらず、投稿フォームの初期値も同じスナップショットに基づくこと。
- 固有素材が外部配信先で表示・再生できても、未登録なら不足を通知すること。共通素材の未登録は不足扱いにしないこと。
- ID未設定でも編集・素材登録ができ、IDの設定・変更後も素材との対応が維持されること。
- 同じシナリオIDを持つ別作品の素材が混ざらず、ID未設定・不正の場合はZIP生成前に修正を促すこと。
- ZIP内のフォルダー構成が正しいこと。
- ZIP内のJSONからシナリオ固有素材を正しく参照でき、共通素材は既存の配信環境で参照できること。

## 10. 実装上の制約

- Playgroundはブラウザー上で動作する既存のWebアプリケーションであり、サーバー側の構成を今回の目的だけで変更しない。
- ローカル素材の管理・ZIP生成は、原則としてブラウザー内で完結させる。
- IndexedDBを主たるデータ保存先とし、LocalStorageに画像・音声の実体を保存しない。
- 既存のシナリオ形式、ディレクトリー構成、試遊処理との互換性を優先する。
- 実装上の判断が必要な点や、既存仕様と矛盾する点が見つかった場合は、独断で仕様を変更せず、変更案と影響を提示する。

実装済みの範囲と残作業は、Playgroundの実装およびブラウザー確認の結果に合わせて本書と入門書を更新する。
