# Playground入門――ブラウザーでゲームブックを作ろう

Playgroundは、ブラウザーで動く「ソーサリアンText」のシナリオ編集環境です。インストールは必要ありません。

物語の場面を表す「シーン」を作り、選択肢でつないでいくことで、読者の選択によって展開が変わるゲームブックを作成できます。文章だけの短い物語から、アイテムや謎解き、戦闘を組み込んだ冒険まで、少しずつ作り込めます。

この記事では、簡単な分岐のあるシナリオを作りながら、Playgroundの基本操作を紹介します。

> **保存・素材管理について**
>
> シナリオはブラウザー内に自動保存され、［素材］タブから作品ごとに画像・音声を登録できます。［エクスポート…］では、シナリオと登録素材をまとめたZIPをダウンロードできます。
>
> ［提出…］では、提出用ZIPの作成と投稿情報の送信を行えます。ZIPをギガファイル便へアップロードした後、投稿情報とURLをオレンジフォームへ送り、別タブで確認・最終送信してください。

## ［1］Playgroundを開く

以下のアドレスにアクセスしてください。

https://snext1220.github.io/stext-next/playground/

画面は、大きく三つの領域に分かれています。

| 領域 | 役割 |
|---|---|
| 上部のツールバー | ［作品…］から新規作成・読み込み・作品切り替え、［エクスポート…］からJSON・ZIPのダウンロード、提出など |
| 左側のフロー図 | シーンと、シーン同士をつなぐ選択肢の表示 |
| 右側の編集エリア | 本文や設定の編集、シナリオの検査、試遊 |

フロー図上部の［編集するシーン］から、編集対象を直接選べます。選ぶと［シーン］タブが開き、フロー図も対象のシーンが見える位置に移動します。

一覧は［定義］のグループごとに区切り、グループは「最初のシーン」のID順、各グループ内はシーンID順（数字は数値順）に並びます。どのグループにも入らないシーンは最後の［グループ未所属］に表示します。範囲が重複するシーンは、それぞれのグループに表示します。グループがない場合も、すべてのシーンをID順で選べます。フロー図自体は絞り込みません。

シーン数が多い場合は、［シーンを検索…］からサマリー・本文・選択肢のキャプションを検索できます。検索結果を選ぶと、［シーン］タブが開き、フロー図もそのシーンへ移動します。英字の大文字・小文字は区別しません。本文はマクロを含む保存内容を検索し、選択肢の前後に置く文章や効果・設定値は検索対象外です。

右側には、次の五つのタブがあります。

| タブ | 内容 |
|---|---|
| シーン | 選択中のシーンの本文、選択肢、入ったときの効果など |
| 定義 | シナリオ全体の基本情報、アイテム、フラグ、敵など |
| 素材 | 作品内で使う画像・音声の登録、差し替え、確認 |
| 検査 | 設定の誤りや、参照先の不足などの確認 |
| 試遊 | 編集中のシナリオを、その場で動かして確認 |

まずは上部の［作品…］を開き、［新しいシナリオ］を選びましょう。始まりのシーン「0」だけを持つシナリオが作成されます。

編集中のシナリオはブラウザー内に自動保存されます。作品を切り替える際にも現在の編集内容を保存するため、新規作成やテンプレートの読み込み後は［作品…］→［作品一覧を開く］から元の作品に戻れます。保存に失敗した場合は、エラーを確認して再試行してください。別の場所にもバックアップしたい場合は、JSONまたはZIPをダウンロードしておきましょう。

### テンプレートから始めても構いません

［作品…］から、テンプレートや公開シナリオを開くこともできます。プルダウンで選んでから、［テンプレートを開く］または［公開シナリオを開く］を押してください。ブラウザー内に新しい作品として取り込まれ、公開されている元の作品を書き換えることはありません。

たとえば、次のようなテンプレートがあります。

- **シンプルサンプル**：短いシナリオで基本構成を確認できます。
- **15sceneサンプル（説明あり）**：説明を読みながら、シナリオの組み立て方を学べます。
- **20sceneサンプル（簡易版）**：用意された骨組みに文章を入れながら作成できます。
- **機能テスト**：さまざまな機能の設定例を確認できます。

テンプレートの一覧は、今後追加・変更されることがあります。

なお、［新しいシナリオ］と［空のテンプレート］では、用意されるシーンの構成が異なります。この記事では［新しいシナリオ］を使います。

## ［2］シナリオの基本情報を入力する

右側の［定義］タブを開き、その中の［基本］を選択します。

まずは、次の三つを入力してみましょう。

| 項目 | 入力例 | 内容 |
|---|---|---|
| タイトル | 森の分かれ道 | シナリオの名前 |
| 作者 | あなたの作者名 | 公開時に掲載する名前 |
| シナリオ ID | forest01 | シナリオを識別するための名前 |

タイトルは、上部の入力欄からも変更できます。

**シナリオ IDとシーン IDは別のものです。** シナリオ IDは作品全体を、シーン IDは作品内の各場面を識別します。

シナリオ IDには、英小文字と数字を使った、ほかの作品と重なりにくい名前をお勧めします。セーブデータや素材の参照にも関係するため、制作の早い段階で決めておくと扱いやすくなります。

［基本］では、このほかにも紹介文、キーワード、BGM、キャラクター作成時の制約などを設定できます。最初からすべてを埋める必要はありません。

### 分からない項目は［？］で確認

入力欄の横にある［？］を押すと、その項目のヘルプを開けます。表形式の項目では、列見出しの［？］から説明を確認できます。

上部の［ヘルプ］からは、説明全体の目次を開けます。

## ［3］始まりのシーンを書く

左側のフロー図で、シーン「0」の箱をクリックします。右側の［シーン］タブに、そのシーンの編集欄が表示されます。

まずは、次のように入力してください。

**サマリー**

```text
森の分かれ道
```

**本文**

```text
あなたは、森の入口に立っている。

道は二つに分かれていた。
右の道からは川のせせらぎが聞こえ、
左の道には古い足跡が続いている。

さて、どちらへ進もうか。
```

サマリーは、フロー図でシーンを見分けるための短い説明です。通常のプレイ画面には表示されません。読者に見せたい文章は、［本文］に書きます。

### 本文にはMarkdownを使えます

Markdownは、簡単な記号で文章を装飾する書き方です。

たとえば、次のように書けます。

```markdown
# 森の入口

目の前には、**二本の道**がある。

- 右の道は川へ続いている。
- 左の道には足跡が残っている。

---

あなたは、しばらく考えた。
```

主な書き方は、次のとおりです。

| 書き方 | 表示 |
|---|---|
| `# 見出し` | 見出し |
| `**大切な言葉**` | 太字 |
| `- 項目` | 箇条書き |
| 空行 | 段落の区切り |
| `---` | 水平線 |
| `![説明](scene01.png)` | 画像 |

**シーンを移動するための選択肢は、本文ではなく［選択肢］欄に作ります。** 本文の中に移動先の番号を書く必要はありません。

## ［4］シーンを追加して、選択肢でつなぐ

次に、分かれ道の先にある二つのシーンを作りましょう。

### 新しいシーンへの選択肢を作る

シーン「0」を選択した状態で、フロー図の上にある［＋ 選択中のシーンから］を押します。

新しいシーンが作られ、シーン「0」からそこへ進む選択肢も追加されます。［シーン］タブ内の［＋ 新しいシーンへ］でも、同じように作成できます。

［新しいシナリオ］から始めた場合、最初に追加されるシーン IDは「10」です。さらにシーン「0」を選び直して同じ操作をすると、「20」が作られます。

それぞれ、次のように入力してみましょう。

| シーン ID | サマリー | 本文 |
|---|---|---|
| 10 | 川辺の休息 | 川辺には、村へ向かう旅人がいた。あなたは旅人とともに森を抜け、無事に村へたどり着いた。 |
| 20 | 森の奥へ | 足跡を追ううちに、辺りは暗くなった。あなたは道を見失い、森の奥で一夜を明かすことになった。 |

### 選択肢の文章を変更する

シーン「0」を選び直し、［選択肢］欄を確認します。

追加された選択肢の［文言］を、次のように変更してください。

| 文言 | 遷移先 |
|---|---|
| 右の道を進む | 10 |
| 左の道を進む | 20 |

「遷移先」は、選択したときに移動するシーンの IDです。フロー図の線に表示される文章も、選択肢の文言に応じて変わります。

### 既存のシーン同士をつなぐ

すでにあるシーンへ選択肢を追加する場合は、フロー図でも操作できます。

1. 移動元のシーンの**右側の点**からドラッグします。
2. 移動先のシーンの**左側の点**につなぎます。
3. 移動元の［シーン］タブで、追加された選択肢の文言を編集します。

［＋ 選択肢］ボタンから作ることもできます。ただし、このボタンで追加した直後の遷移先は、現在のシーン自身です。目的のシーン IDに変更してください。

### フロー図と選択肢は連動しています

現在のPlaygroundでは、フロー図の線は、シーン内の選択肢から作られます。

旧版のような独立した［リンク］タブはありません。選択肢を修正するには、**移動元のシーンを選び、その［選択肢］欄を編集する**と覚えておきましょう。

## ［5］エンディングを設定する

今回は、シーン「10」と「20」を物語の終わりにします。

各シーンを選び、［シーン］タブの［そのほか］にある［エンディング］を設定してください。

- シーン「10」：ハッピーエンド
- シーン「20」：バッドエンド

設定すると、フロー図の箱にも「HAPPY」「BAD」などの表示が付きます。

**選択肢がないだけでは、エンディングを設定したことにはなりません。** 物語を終えるシーンでは、［エンディング］を指定しましょう。

これで、次のような小さなゲームブックができました。

```text
             ┌─ 10：川辺の休息 → ハッピーエンド
0：分かれ道 ─┤
             └─ 20：森の奥へ   → バッドエンド
```

## ［6］［検査］で設定を確認する

右側の［検査］タブを開きます。

ここでは、たとえば次のような問題を確認できます。

- 遷移先のシーンが存在しない
- 条件式の書き方が正しくない
- 使用しているアイテム、フラグ、敵などが定義されていない
- 選択肢がなく、エンディングにもなっていない

問題には［エラー］と［警告］があります。まずエラーを直し、警告も内容を確認してください。

シーンに関係する問題では、表示されたシーン番号を押すと、そのシーンの編集画面へ移動できます。

ただし、**［検査］で問題がなくても、物語が意図どおりに動くとは限りません。** 行き止まり、条件の設定ミス、読みづらい文章などは、実際に遊んで確認する必要があります。

## ［7］［試遊］で遊んでみる

右側の［試遊］タブを開き、［最初から試遊］を押します。

現在のPlaygroundでは、別のタブへ移動せず、編集画面の中で本文と選択肢を確認できます。まず右の道を選び、ハッピーエンドへ進めることを確かめてください。もう一度［最初から試遊］を押し、左の道も確認しましょう。

［状態］を開くと、キャラクターの能力値、アイテム、フラグ、星などを確認できます。

分岐の確認には、［試遊の開始状態を指定］を開いて、アイテム・フラグ・パラメーター・星を設定できます。値を指定してから試遊を始めると、その状態でシーン「0」に入り、選択中のシーンがあれば続けて移動します。空欄のパラメーターは定義の初期値を使い、空欄の星は初期値のままです。指定した状態や試遊の進行は、プレイヤーのセーブデータには保存されません。

### 途中のシーンから確認する

フロー図でシーン「10」などを選んでから［試遊］を開くと、［§10 から試遊］のようなボタンが表示されます。

長いシナリオで、修正した場面をすぐに確認したいときに便利です。

ただし、途中からの試遊は、**それ以前の場面を通ってきた状態の再現ではありません。** 前の場面で手に入るアイテムやフラグを前提にする分岐は、開始状態を指定するか、最初から通して確認してください。

### 試遊と正式なプレイの違い

試遊の進行状況は、プレイヤーのセーブデータには残りません。

また、現在の試遊は簡易的な確認機能です。戦闘は敵の名前を表示するだけで、実際の戦闘操作はできません。「戻る」の選択肢による直前のシーンへの移動にも対応していません。

画像や音声は登録素材を使って試遊でも確認できます。BGM・効果音には再生コントロールが表示されるので、再生ボタンを押してください。自動再生ではありません。戦闘、魔法、アイテムの使用などを含めた最終確認は、プレイヤー側でも行ってください。

## ［8］アイテムやフラグで分岐を作る

文章と選択肢だけでもゲームブックは作れますが、「鍵を持っていると扉を開けられる」といった条件を加えると、冒険の幅が広がります。

ここでは、基本的な考え方を紹介します。

### アイテムを定義する

［定義］→［アイテム］を開き、［＋ アイテムを追加］を押します。

例として、次のアイテムを作ります。

| 項目 | 値 |
|---|---|
| ID | i01 |
| 名前 | 古い鍵 |
| 説明 | 森の小屋で見つけた鍵。 |

表の入力欄は、そのままクリックして編集できます。行を削除するには、右端の［×］を押します。

次に、鍵を手に入れるシーンの［シーンに入ったときの効果］で、［アイテム］に次のように入力します。

```text
i01
```

これで、そのシーンに入ったときに「古い鍵」を入手します。

### アイテムを持っているときだけ選択肢を出す

扉のあるシーンに、次の通常の選択肢を作ります。

- 文言：鍵で扉を開ける
- 遷移先：扉の先のシーン ID
- 条件：`i01`

この選択肢は、「古い鍵」を持っているときだけ表示されます。

反対に、鍵を持っていないときだけ表示したいなら、条件を次のようにします。

```text
!i01
```

### フラグは「出来事を覚える印」

フラグは、「村人から話を聞いた」「仕掛けを動かした」といった出来事を記録するための印です。

［定義］→［フラグ］で「f01」などを作り、記録したいシーンの［フラグ］欄に次のように入力します。

```text
f01
```

その後の選択肢で条件を `f01` にすれば、その出来事を経験したときだけ表示できます。

アイテムやフラグを取り除きたい場合は、シーンの効果に `-i01`、`-f01` のように、先頭に `-` を付けて指定します。

条件は組み合わせることもできます。

```text
f01&i01
```

これは「f01があり、かつi01を持っている」という条件です。詳しい書き方は、条件欄の［？］から確認してください。

> **条件付きの選択肢には、行き止まりに注意**
>
> 条件を満たさないと、選択肢そのものが表示されません。ほかに進める道がない場合は、プレイヤーが先へ進めなくなります。条件を満たす場合と満たさない場合の両方を確認しましょう。

## ［9］敵や罠を設定する

モンスターを登場させるには、まず［定義］→［敵］で敵の情報を作成します。

［＋ 敵を追加］を押し、ID、名前、説明、属性、攻撃方法、ダメージ式、HPなどを入力します。初めて設定するときは、テンプレートの例と各列の［？］を参考にすると分かりやすいでしょう。

作成した敵の IDが「m01」なら、登場させたいシーンの［敵］欄に次のように入力します。

```text
m01
```

複数の敵は、カンマ区切りで指定できます。

```text
m01, m02
```

敵の**定義**と、その敵を**どのシーンに登場させるか**は別の設定です。表に敵を追加しただけでは、物語には登場しません。

設定後は［検査］で参照先を確認し、戦闘の動作はプレイヤーで確かめてください。

## ［10］画像・音声素材を使う

本文の画像は、次のように指定します。

```markdown
![森の小屋](hut.png)
```

この例では、シナリオ固有の `capture` フォルダーに置く「hut.png」を使います。

独自のBGMは、`bgm` フォルダーにMP3ファイルを用意します。BGM欄には、拡張子を除いた名前を入力します。

```text
main
```

これは「main.mp3」の指定です。

STextの共通BGMを使う場合は、先頭に `@` を付けます。

```text
@field05
```

共通BGMの一覧は、BGM欄のヘルプから確認できます。

### 素材を登録する

右側の［素材］タブには、本文のMarkdown画像やBGM・効果音の設定から参照されている素材が表示されます。

たとえば「森の小屋」の画像は、次の手順で登録します。

1. シーンの本文に `![森の小屋](hut.png)` と書きます。
2. ［素材］タブを開き、［シナリオから参照されている素材］の `capture/hut.png` を探します。
3. ［素材を指定…］を押し、使いたいPNG画像を選びます。
4. ［登録済み］と画像のプレビューが表示されたことを確認します。
5. ［試遊］タブで、本文の画像が表示されることを確認します。

参照先から指定する場合は、元ファイルの名前が異なっていても、その参照先に登録されます。ただし、拡張子は一致させてください。たとえば `capture/hut.png` にはPNG画像を指定します。登録しても本文の参照名は変わりません。

### 参照していない素材を追加する

紹介画像など、まだ本文に書いていない素材も登録できます。

［素材を追加］の［素材の種類］を選び、［ファイルを登録…］からファイルを指定してください。

| 種類・登録先 | 用途 |
|---|---|
| 挿絵・画像（`capture/`） | 本文の画像、紹介画像など |
| BGM（`bgm/`） | 独自のBGM |
| 効果音（`bgm/se/`） | 独自の効果音 |
| キャラクター画像（`chara/`） | 独自のキャラクター画像 |

この方法では、元のファイル名をそのまま使います。たとえばBGMを選び「main.mp3」を登録すると、登録先は `bgm/main.mp3` です。同じ登録先に同名の素材がある場合は、差し替えるか確認します。

画像はPNG・JPEG・GIF・WebP、音声はMP3・OGG・WAV・M4A・AACに対応し、**1ファイル50MB以下**です。空のファイルや、登録先と形式が合わないファイルは登録できません。音声の拡張子を省略した設定はMP3として扱うため、OGGなどを使う場合は、BGM欄にも `main.ogg` のように拡張子を含めて指定してください。

素材を登録しただけで、本文やBGMの設定が自動的に追加されるわけではありません。実際に使うときは、シーンや基本情報にも参照を設定します。

### 素材を確認・差し替え・削除する

登録した素材は［素材］タブでプレビューできます。画像は［試遊］にも反映され、BGM・効果音は［素材］と［試遊］の再生コントロールで試聴できます。再生できる形式はブラウザーにも依存します。

登録済みの素材には、［差し替え…］と［削除］があります。差し替え・削除の前には確認が表示されます。シナリオから参照されていない登録素材は、下部の［登録済み素材］に表示され、これらもZIPに収録されます。

［削除］はブラウザー内の素材を取り除く操作です。本文やBGMの参照は残るため、必要なら設定も修正してください。試遊では登録素材を優先し、未登録の場合は従来の配信先を参照します。そこで表示・再生できても、素材が登録されていなければZIPには入りません。

素材の登録は、元ファイルを変更せず、**ファイルの中身をPlayground内に保存**します。そのため、元ファイルを移動・削除しても登録済みの素材を利用できます。素材はこのブラウザーに保存され、登録しただけでサーバーへアップロード・公開されることはありません。

## ［11］シナリオを保存する

現在のPlaygroundで扱う正式なシナリオ形式は、**JSON（stext/2）**です。

旧版では編集用JSONと実行用XMLを使い分けていましたが、現在はJSONが編集・実行の両方に使われます。新しいシナリオをXMLへ書き出す必要はありません。

### 自動保存と作品の切り替え

シナリオの編集内容と登録素材は、このブラウザーのIndexedDB（ブラウザー内の保存領域）に保存されます。名前を付けて手動保存する操作は不要です。

シナリオを編集すると、画面上部の表示が［変更を保存します…］、［このブラウザーに保存中…］、［このブラウザーに保存済み］へ変わります。**ブラウザーを閉じる前に、保存済みの表示を確認してください。** 素材は［素材］タブでも登録結果やエラーを確認します。

自動保存に失敗した場合は、エラーの内容を確認し、［再試行］を押します。容量不足なら、必要な作品を先にバックアップし、不要な素材や作品を削除してから再試行してください。保存できない間は、再読み込みやブラウザーを閉じる操作を避け、必要に応じてJSONをダウンロードして編集内容を退避します。

保存済みの作品へ戻るには、次のように操作します。

1. ［作品…］→［作品一覧を開く］を選びます。
2. タイトル、シナリオID、更新日時を確認し、開きたい作品を押します。

新規作成、テンプレート・公開シナリオ・ファイルの読み込みでは、それぞれ別の作品が作られます。同じタイトルやシナリオIDの作品でも、既存の作品やその素材を上書きしません。続きの編集には、ファイルを再度読み込むのではなく、作品一覧から開いてください。

作品一覧の［削除］では、確認後に**その作品と登録素材が一緒に削除されます。** 編集中の作品を削除した場合は、空の新しいシナリオに切り替わります。作品や素材の削除は［↶］では戻せないため、必要なデータは先にZIPで退避してください。

### JSONまたはZIPをダウンロードする

上部の［エクスポート…］から、用途に合った方法を選びます。

| 操作 | 内容・用途 |
|---|---|
| 作品一式をZIPでダウンロード | シナリオ本体と登録素材をまとめます。作品のバックアップや提出に使います |
| シナリオだけをJSONでダウンロード | シナリオ本体だけを取り出します。JSONの確認・編集などに使います |

通常はZIPをお勧めします。JSONには画像・音声ファイルの中身は含まれません。

ZIP作成時と提出画面を開くときは、保存を完了し、シナリオと素材をその時点の内容で確定します。この準備中は、編集操作が一時的に無効になります。ZIP作成中は進行状況が表示されます。ダウンロード開始の案内が出たら、ブラウザーのダウンロード一覧や保存先を確認してください。

ZIPのファイル名は `forest01.zip` のようにシナリオIDから付けられ、中身は次の構成になります。

```text
forest01/
  scenario.json
  capture/
    hut.png
  bgm/
    main.mp3
    se/
      door.mp3
```

使わない素材フォルダーは不要です。キャラクター画像を登録した場合は `chara/` も含まれます。

ZIPには、その作品に登録した素材を**未参照のものも含めてすべて**収録します。不要な素材や公開したくないファイルが混ざっていないか、提出前に確認してください。

参照素材が未登録の場合は、不足する素材の一覧と、このまま作成するかの確認が表示されます。作品一式をそろえるには、作成を中止して［素材］タブで登録してください。そのまま作成したZIPには、不足素材は含まれません。

`@field05` などの共通素材や外部URLの素材は、自動でダウンロードして同梱することはありません。公開シナリオを取り込んだ場合も、JSONの読み込みだけで固有素材が登録されるわけではありません。

シナリオIDが未設定、またはフォルダー名として使えない場合はZIPを作成できません。［定義］→［基本］で、`forest01` のような安全なIDに修正してください。素材の読み込み失敗やファイル名の衝突などで作成できない場合も、画面に表示されるエラーを確認します。

### 自動保存だけに頼らない

ブラウザー内の保存は、サーバーへのバックアップではありません。

ブラウザーのデータを削除したり、別のブラウザーや端末を使ったりすると、以前の編集内容を利用できない場合があります。

**作業の区切りで、JSONまたはZIPをパソコンにもダウンロードしておきましょう。** JSONには素材の実体は含まれません。作品一式をバックアップする場合はZIPを使い、未登録素材の警告も確認してください。

### ファイルから編集を再開する

［作品…］→［ファイルを選択…］からJSONを読み込むと、新しい作品として編集を始められます。

現在、ZIPをそのまま読み込む機能はありません。ZIPから復元する場合は、パソコンで展開し、中の `scenario.json` を読み込んでから、［素材］タブで画像・音声を登録し直してください。未参照素材も復元したい場合は、［素材を追加］から登録します。

## ［12］作品を提出する

作品ができたら、まず［検査］と［試遊］で確認し、JSONやZIPのバックアップを保存してください。

**ブラウザー内への保存、提出の受付、書庫への公開は、それぞれ別の状態です。** 自動保存やZIPのダウンロードだけで作品が提出・公開されることはありません。

現在は、作品ファイルをPlaygroundから投稿サーバーへ直接送る方式ではありません。**ZIPを利用者自身がギガファイル便にアップロードし、Playgroundからは投稿情報とダウンロードURLだけを送信します。**

### Playgroundから提出する

上部の［提出…］を押すと、シナリオと素材を保存して、その時点の内容で提出画面が開きます。作品名、シナリオID、収録素材の件数と容量を確認してください。表示される容量は登録素材の合計で、生成後のZIPサイズとは異なります。

作品名とシナリオIDは、管理者がZIP内の `scenario.json` から確認するため、受付フォームには送信しません。これらを修正したい場合は提出画面を閉じて編集し、改めて開いてください。

1. ［ZIPを作成してダウンロード］を押し、保存先を確認します。未登録の参照素材がある場合は確認が表示されます。
2. ［ギガファイル便を開く］からZIPをアップロードし、保持期間を**7日以上**に設定します。必要に応じてダウンロードキーを設定し、アップロードが完了してからURL・保持期間・キーを控えてください。
3. 提出画面に戻り、以下の投稿情報とダウンロード情報を入力します。
4. ［作品を提出］を押し、別タブのオレンジフォームで内容を確認して最終送信します。

| 項目 | 入力内容 |
|---|---|
| ペンネーム（作者名） | 必須。［定義］の作者名が初期値として入ります |
| 連絡先（メールアドレス） | 必須。管理者が連絡できるアドレス |
| 分類 | 必須。カンマ区切りで入力します。キーワードが初期値になります |
| 難易度 | 1（易）〜5（難）。最初は3（普通） |
| シナリオ紹介 | 必須。2〜300文字。［定義］の紹介文が初期値になります |
| 作者より | 必須。80文字程度を目安に、作品についてのひとこと |
| ダウンロードURL | 必須。アップロード済みZIPのHTTPSのギガファイル便URL |
| 保持期間 | 必須。初期値は `7`。`7`、`30` など、実際に設定した7日以上の日数（`7日` なども入力可） |
| ダウンロードキー | 任意。ギガファイル便で設定した場合に入力 |

投稿情報の入力欄を変更しても、シナリオ本体の定義は変わりません。作者名や紹介文を作品内でも変更したい場合は、［定義］側も修正し、ZIPを作り直してください。

連絡先やダウンロード情報は、シナリオの保存データや提出用ZIPには含めません。ダウンロードキー以外の入力内容（メールアドレスを含む）は、このブラウザーのCookieにプロジェクトごとに30日間保存し、画面を閉じても復元します。保存期間は入力の変更時から数えます。ダウンロードキーは開くたびに入力してください。保存に失敗した場合は警告を表示するので、画面を閉じる前に必要な情報を控えます。

［保存した入力内容を削除］で、この作品のCookieを削除して入力欄を初期値に戻せます。ほかの作品の投稿内容には影響しません。共用端末では利用後に削除してください。

### 受付結果と公開

［作品を提出］を押すと、投稿情報とダウンロードURLを別タブの確認画面へ送ります。内容を確認して、**オレンジフォーム側で最終送信**してください。ZIP本体はこの受付先には送りません。

入力の不備はPlayground側に表示します。通信や受付のエラーは別タブで確認してください。別タブが開かない場合は、ブラウザーの設定を確認します。元の画面には入力を残します。再試行前に受付済みでないか確認し、重複投稿に注意してください。

最終送信後は、別タブの受付結果と連絡先に届く確認メールを確認してください。メールが届かない場合は迷惑メールフォルダーも確認します。**Playground側では受付・メール配送の完了を確認できません。** 受付と公開は別であり、公開前に管理者が内容を確認します。

確認メールはオレンジフォームの自動返信設定で送ります。仮のプレイURLは発行しません。

### GitHub Discussionsから提出する

オレンジフォームが利用できない場合などは、既存のGitHub Discussionsを代替の提出先として利用できます。GitHubのアカウントが必要です。

<https://github.com/snext1220/stext/discussions/299>

1. 提出画面の下部にある［GitHub Discussionから投稿］を開きます。
2. スレッドの案内に従って、作品名・作者名・紹介などの公開用の投稿情報を入力します。
3. ZIPを投稿欄に添付し、収録内容と投稿文を確認して提出します。

**メールアドレスやダウンロード情報は公開投稿に記載しないでください。** 提出文をコピーする機能はありません。

画像や楽曲などを使った場合は、利用条件を確認し、［定義］→［ライセンス］に必要なクレジットも記載しましょう。

# 覚えておくと便利な機能

## 選択肢の並べ替えと削除

［シーン］タブの各選択肢には、［↑］［↓］［×］があります。

- ［↑］［↓］：表示順を変更
- ［×］：選択肢を削除

フロー図の配置順と、プレイ画面の選択肢の表示順は別です。読者に見せたい順番は、選択肢の欄で調整してください。

## 特殊な選択肢

選択肢の種類を変更すると、通常の分岐以外も作れます。

| 種類 | 用途 | 主な入力内容 |
|---|---|---|
| 通常 | 指定のシーンへ進む | 文言、遷移先 |
| ランダム | 複数の候補から移動先を選ぶ | 文言、遷移先をカンマ区切り |
| 番号入力 | プレイヤーが番号を入力する | 移動できる番号 |
| 文字入力 | 謎解きなどで答えを入力する | 正解、正解時と不正解時の遷移先 |

たとえば、ランダムの遷移先を次のようにすると、「10」「20」「30」のいずれかへ進みます。

```text
10, 20, 30
```

旧版のように、複数のリンクへ同じ表示順序を設定してまとめる必要はありません。一つの選択肢の中に、必要な情報を入力します。

## 本文に記法を差し込む

本文欄の上には、［名前］［赤字］［ルビ］［画像］［太字］などのボタンがあります。

文章を選択してから［太字］を押すと、選択部分が `**` で囲まれます。［名前］では、キャラクター名を表示する `${name}` が挿入されます。

条件付きの文章や、別シーンの本文を読み込む記法も差し込めます。挿入されたIDや仮の文章は、そのまま使わず、シナリオに合わせて修正してください。

## フロー図を整理する

シーンの箱は、ドラッグして移動できます。

図が見づらくなったら、［自動で並べる］を使って配置し直せます。ただし、手作業で整えた配置も変わるため、必要に応じて使い分けましょう。

右側の編集エリアとの境界をドラッグすると、幅を調整できます。本文を書くときは編集エリアを広く、分岐を考えるときはフロー図を広くすると便利です。

## 元に戻す・やり直す

上部の［↶］［↷］で、編集操作を取り消したり、やり直したりできます。

キーボードでは、次の操作も使えます。

- `Ctrl+Z`：元に戻す
- `Ctrl+Shift+Z`：やり直す
- macOSでは、`Ctrl`の代わりに`Command`

入力欄の中では、ブラウザーの文字入力の取り消しが優先されます。また、別のシナリオを開くと編集履歴はリセットされるため、履歴をバックアップ代わりには使わないでください。

## シーン IDの付け方

シーン IDは、作品内で重ならないようにします。連番にする必要はありません。

たとえば、村の場面を「100」番台、森の場面を「200」番台にすると、制作中に場所を把握しやすくなります。

ただし、特別な用途の番号には注意してください。

- `0`：始まりのシーン
- `90000`：選択肢の遷移先に指定すると「戻る」
- `99999`：共通の戦闘ルール

通常の場面では、将来の予約も考慮して9万番台を避けると安心です。

IDを変更したい場合は、［シーン ID］欄を書き換えて［変更］を押します。選択肢の遷移先などの参照も、まとめて更新されます。

# 旧Playgroundから移行する方へ

現在のPlaygroundは、旧Playground Flowをそのまま再現したものではありません。主な違いは、次のとおりです。

| 旧版 | 現在のPlayground |
|---|---|
| 基本情報や各定義が上位のタブに並ぶ | ［定義］タブの中にまとめて配置 |
| 独立した［リンク］タブで編集 | 移動元シーンの［選択肢］欄で編集 |
| 別タブでシナリオを実行 | ［試遊］タブで簡易確認 |
| デバッグ画面でItems／Flagsなどを入力 | ［試遊の開始状態を指定］でアイテム・フラグ・パラメーター・星を設定 |
| JSON・XMLなどへ書き出す | 正式形式はJSON（stext/2） |
| ブラウザーへの手動保存・マイストレージ | 作品ごとの自動保存と［作品一覧を開く］ |
| シナリオ・素材を直接投稿する | ZIPをギガファイル便へアップロードし、投稿情報とURLを提出する |
| Editorへ切り替えて編集 | 旧Editorへの切り替えはない |
| シーン IDのシャッフル、範囲を絞った表示 | これらの機能はない |

旧形式の `scenario.xml` や旧PlaygroundのJSONは、［作品…］の［ファイルから読み込む］にある［ファイルを選択…］から読み込むと、新しい形式へ変換して編集できます。

変換したシナリオは、［検査］と［試遊］で確認し、JSONまたはZIPをダウンロードしてください。ZIPに画像や音声を含める場合は、先に［素材］タブから登録します。

# まずは短い物語を完成させよう

最初から、戦闘や複雑な謎解きをすべて組み込む必要はありません。

まずは数シーンで、次の流れを一通り試してみてください。

1. シーンを書く
2. 選択肢でつなぐ
3. エンディングを設定する
4. ［検査］で設定を確認する
5. ［試遊］で両方の分岐を遊ぶ
6. JSONまたはZIPをダウンロードする

短い作品を最後まで作ってから、アイテム、フラグ、敵、画像や音楽を加えていくと、各機能の役割を理解しやすくなります。

まずは、あなた自身の「分かれ道」から、一つの冒険を作ってみましょう。
